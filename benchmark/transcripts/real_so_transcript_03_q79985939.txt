Title: IDispatch::Invoke crashes server-side COM framework for basic IAccessible implementation for child count 1+ for IAccessible::get_accChildCount
================================================================================

I'm trying to implement basic accessibility support for a custom GUI (server-side) - all GUI controls are custom/non-MS - via `IAccessible`. However, my COM framework keeps crashing.  Even pure skeletal definitions crash.


The crash appears to be centered around `IDispatch::Invoke()`. Whenever `IAccessible::get_accChildCount()` is called and returns 1 or more for the child count, `IDispatch::Invoke()` is called thereafter and crashes the app.  Even a bare "non-implemented" version of `IDispatch` crashes at `Invoke()`.  The value for `iid` for `Invoke()` is also not `IID_NULL`.


I'm using "Accessibility Insights for Windows" and "Visual UIA Verify" as client apps to probe my app/test the COM framework.


I code in Borland Delphi 3 Professional (32-bit) using Object Pascal, and wish to implement the COM framework as pure binary vTables and standard COM functions using `stdcall`.


`OleVariant` seems unstable in Delphi 3. I have swapped it out for `tcomvar` (16 bytes for 32-bit and 24 bytes for 64-bit).  I have tried various different function parameter definitions, higher-level object/interface definitions, even imported `IAccessible` using the "Import Type Library" function in Delphi 3, but all to no success.  I even tried the COM framework in Borland Delphi 7 with no change, it still crashes.


I am new to COM, but understand the basic design principal governing its function.


However, everything I have tried to date has failed to fix the `IDispatch::Invoke()` error.  I suspect it is something simple I have overlooked.  But trying to get precise, accurate, and detailed information at this low level in Object Pascal from the Internet has been a real challenge.


I have tried Copilot and Google's AI extensively over days. Both are helpful, but lack the technical background and accuracy to get right down to the nitty gritty detail where it counts.


I could simply deny the request for the `IID_IDispatch` interface in `QueryInterface()`, but I suspect it is required for proper/broad client app support, e.g. scripting engines etc, and also, I'd like to understand what the error actually is, and what I have done wrong, so I can fix it.


I've included a stripped down demo version of the COM framework hooked to a standard `TForm` for the `WM_GETOBJ` message for testing purposes only.


Any help is much appreciated.
